# Terminal Safety Rule

## Назначение

Это правило снижает риск повреждения исходных файлов при работе через Terminal на macOS.

## Обязательное правило

Не использовать heredoc и длинные многострочные вставки в Terminal для полной замены исходных файлов, конфигурации, миграций и инженерной документации.

Причина: при обрыве вставки, зависании редактора, потере соединения или ошибке закрывающего маркера shell может записать неполный или повреждённый файл.

## Разрешённые способы полной замены файла

Использовать один из следующих способов:

1. Готовый проверенный файл с последующим копированием в репозиторий.
2. Проверенный скрипт, который создаёт файл целиком и завершает работу с ненулевым кодом при ошибке.
3. Изменение через GitHub с обязательной проверкой полного содержимого и diff.
4. Редактор кода — только когда файл остаётся доступен для проверки перед сохранением.

## Обязательная защита

Перед заменой существующего файла:

```bash
cp path/to/file path/to/file.backup
```

После замены выполнить:

```bash
npm run lint
npx tsc --noEmit
npm run build
git diff --check
git diff -- path/to/file
```

Для миграций дополнительно выполнить Migration Check (проверка миграции — проверка порядка, повторяемости, отката и влияния на данные).

## Запрещённый шаблон

Не использовать для больших или критичных файлов:

```bash
cat > path/to/file <<'EOF'
...
EOF
```

## Критерии завершения

Изменение считается завершённым только когда:

- файл полностью проверен;
- Lint (статическая проверка кода) пройден;
- TypeScript (проверка типов) пройден;
- Production Build (промышленная сборка) пройден;
- Diff Check (проверка различий) пройден;
- Migration Check выполнен, когда изменение затрагивает базу данных;
- создан Git commit (фиксация изменения в Git);
- инженерная документация обновлена.
