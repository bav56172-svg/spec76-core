## Измеримая проблема

В Release 0.4 отсутствует активный безопасный серверный контур для ИИ-запросов. Нельзя открывать ИИ-функции пользователям без проверки личности, прав, входных данных, лимитов, аудита и атомарного учёта использования.

## Пользовательская ценность

### Заказчик

Заказчик получает понятный ИИ-инструмент внутри проекта без доступа к техническим ключам, внутренним лимитам и инфраструктурной сложности.

### Исполнитель

Исполнитель получает ИИ-помощь в контексте доступного ему проекта без возможности выйти за границы разрешённых данных и действий.

## Граница Capability

Первый этап включает:

1. один серверный AI API route (маршрут AI API — серверная точка приёма запроса);
2. Authentication (аутентификация — проверка личности пользователя);
3. Authorization (авторизация — проверка доступа к компании и проекту);
4. Validation (валидация — проверка структуры и ограничений входных данных);
5. серверное хранение ключа AI provider (поставщик ИИ-модели — внешний сервис обработки запросов);
6. ограничение размера запроса;
7. атомарное резервирование и завершение учёта использования;
8. RLS (безопасность на уровне строк — правила доступа к отдельным записям базы);
9. единый безопасный формат ответа и ошибок;
10. Audit Event (событие аудита — запись значимого действия без секретов и полного содержимого запроса).

## Вне границы

- автономные агенты;
- автоматическое изменение проектов, задач и документов;
- юридические, финансовые, репутационные и безопасностно значимые решения;
- потоковая генерация;
- многоагентные сценарии;
- долговременная память ИИ;
- пользовательский биллинг за ИИ;
- административный интерфейс тарифов;
- сохранение полного текста запроса и ответа в журнале использования.

## Архитектурные зависимости

1. C-002 Identity & Access.
2. C-005 User Experience Platform.
3. C-003 Workflow Platform.
4. C-004 Audit Platform.
5. C-007 Knowledge Platform только после отдельного допуска хранения данных.
6. Единый `ServiceResult<T>` сервисного слоя.
7. Supabase как источник истины для данных.
8. ADR-026 Russian Production Data Boundary: конкретный пользовательский поставщик и передача ему данных требуют отдельного юридического и архитектурного допуска.

## Безопасность

- идентичность определяется сервером;
- доступ проверяется для конкретной компании и проекта;
- клиент не передаёт доверенные `user_id` и права;
- ключ поставщика ИИ существует только на сервере;
- пользователи не могут напрямую изменять записи использования;
- атомарные операции выполняются серверной функцией;
- полный текст запроса и ответа не записывается в `ai_usage`;
- внутренние ошибки и секреты не возвращаются клиенту;
- значимые решения требуют подтверждения человека.

## Предварительная модель данных

Логическая запись использования: `id`, `request_id`, `user_id`, `company_id`, `project_id`, `operation`, `status`, `provider`, `model`, `input_units`, `output_units`, `total_units`, `created_at`, `completed_at`.

Точные типы, ограничения, индексы и жизненный цикл определяются миграцией после Migration Readiness Check (проверка готовности миграции).

## UX-принципы

- пользователь видит простое действие и понятный результат;
- пользователю не показываются токены, ключи, RLS и внутренняя оркестрация;
- при отказе отображается безопасное понятное объяснение;
- ИИ явно обозначается как помощник;
- результат ИИ не считается окончательным значимым решением.

## Российская производственная граница

- Capability может развиваться через заменяемый Provider Adapter (адаптер поставщика — внутренний интерфейс смены модели);
- активный OpenAI API не является частью утверждённого российского производственного контура;
- ключ и пользовательские данные нельзя передавать конкретному поставщику до юридического, архитектурного и безопасностного допуска;
- первичные персональные данные граждан Российской Федерации должны находиться в российском производственном контуре в соответствии с `SPEC76-ADR-026`;
- обход территориальных ограничений поставщиков запрещён;
- локальная разработка контракта, защитных отказов и тестов без отправки пользовательских данных внешней модели разрешена внутри C-006.
