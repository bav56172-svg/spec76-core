## Подтверждённое исходное состояние на 2026-07-23

Architecture Gate от 2026-07-23 подтвердил:

- активных AI API routes в `app/api` нет;
- активного AI provider нет;
- миграции и подтверждённой схемы `ai_usage` нет;
- RLS и атомарных функций `ai_usage` нет;
- `services/usageBilling.ts` читает `ai_usage`, но изменение использования намеренно заблокировано;
- Lint, TypeScript и Production Build проходят;
- рабочее дерево после аудита не изменилось.

## Решение Platform Owner

Утверждена минимальная граница C-006 AI Request Foundation. Реализация начинается с безопасной платформенной основы и не включает автономные действия.

## Этапы реализации

1. Architecture Package (архитектурный пакет): Capability, ADR, модель угроз и критерии завершения.
2. Data Security Foundation (основа безопасности данных): миграция `ai_usage`, RLS, права, атомарные функции, rollback и проверки.
3. Protected AI API (защищённый AI API): один маршрут, Authentication, Authorization, Validation и безопасные ошибки.
4. Provider Integration (интеграция поставщика): одна ограниченная операция, таймаут, лимиты и защитный отказ.
5. Verification and Documentation (проверка и документация): тесты, инженерные проверки, журналы и решение Platform Owner.

## Модель угроз первого этапа

| Угроза | Обязательная защита |
|---|---|
| неавторизованный запрос | серверная проверка пользователя |
| доступ к чужому проекту | проверка членства и роли |
| подмена `user_id` | идентификатор берётся из серверной сессии |
| обход лимита конкурентными запросами | атомарная серверная операция |
| прямая запись `ai_usage` | revoke, RLS и закрытая функция |
| утечка ключа поставщика | только серверная переменная окружения |
| утечка содержания запроса | не сохранять полный текст в usage-журнале |
| раскрытие внутренних ошибок | стабильный безопасный код ошибки |
| автономное значимое действие | запрет в границе первого этапа |
| неконтролируемые затраты | лимиты, резервирование и защитный отказ |

## Блокирующие условия до реализации миграции

- утверждённый ADR;
- подтверждённая фактическая модель пользователей, компаний, проектов и членства в Supabase;
- определённый источник прав доступа к проекту;
- определённый жизненный цикл reservation → completed/failed;
- rollback-процедура;
- тестовый план RLS;
- решение Platform Owner по поставщику и допустимой операции.

## Текущий статус на 2026-08-11

Завершено и подтверждено:

- базовая миграция `ai_usage` применена;
- lifecycle migration (миграция жизненного цикла) добавила `request_id`, `status`, `completed_at`, атомарные `reserve_ai_usage` и `finalize_ai_usage`;
- RLS, FORCE RLS, запрет клиентской записи и права `service_role` проверены;
- технический rate limit (лимит частоты запросов) `10 запросов за 60 секунд на пользователя` реализован атомарно;
- локальная и production verification (производственная проверка) пройдены;
- единый `ServiceResult<T>` существует в активном сервисном слое.

Не завершено:

- один пользовательский защищённый AI API route;
- Authentication, Authorization и Validation полного пользовательского ИИ-сценария;
- Provider Adapter (адаптер поставщика);
- подключение допустимого пользовательского ИИ-поставщика;
- успешные и защитные интеграционные тесты маршрута.

После принятия `SPEC76-ADR-026` OpenAI или иной конкретный пользовательский поставщик не может быть включён автоматически. Передача пользовательских данных поставщику требует отдельного юридического, архитектурного и безопасностного допуска. Разработка внутреннего контракта, авторизации, валидации и защитного отказа без внешней отправки данных остаётся допустимой.
