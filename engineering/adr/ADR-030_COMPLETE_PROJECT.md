## Контекст

Модуль рейтингов и отзывов (OP-037, пробел оригинального ТЗ) должен позволять писать отзыв только о завершённой работе. Статус `completed` допустим в CHECK-ограничении `projects.status`, но ни один путь в коде не переводит проект в него: `accept_offer()` создаёт проект как `active`, дальше статус не меняется (прямо зафиксировано в заголовке миграции OP-025).

После OP-035 политика UPDATE на `projects` разрешает заказчику (`owner_id`) менять любые колонки, включая `status`. Без защиты заказчик мог бы пометить проект завершённым напрямую, без проверок и записи в аудит, и любой гейт «отзыв только после завершения» потерял бы смысл.

## Решение

1. **Функция `complete_project(p_project_id)`** (security definer). Вызывать может только заказчик (`projects.owner_id = auth.uid()`). Разрешённые исходные статусы: `active`, `in_progress`. Повторный вызов для уже завершённого проекта — без эффекта (идемпотентность).
2. **Guard-триггер `projects_status_transition_guard`** по образцу OP-025: в `completed` статус можно перевести только изнутри `complete_project()` (через транзакционный `app.internal_status_transition`); из `completed` допустим только переход в `archived`. Прочие переходы не ограничиваются: процесс отмены и архивации ещё не построен, ограничения для него были бы догадкой.
3. **Аудит**: запись в `audit_log` (`entity_type = 'projects'`, `action = 'complete'`, OP-026). Событие `project_status_changed` в `project_activities` пишет уже существующий триггер.
4. **UI**: кнопка «Завершить проект» на странице проекта, видна только заказчику при статусах `active` и `in_progress`, с подтверждением. Права проверяет функция БД, UI лишь скрывает кнопку.

## Альтернативы

- **Завершает исполнитель.** Отклонено: исполнитель заинтересован в завершении и последующем отзыве о себе; подтверждение результата принадлежит заказчику.
- **Двустороннее подтверждение.** Отклонено на первом этапе: усложняет процесс без запроса в ТЗ. Можно добавить позже без изменения контракта `completed`.
- **Только RLS без функции.** Отклонено: RLS не может записать аудит и не отличает «через функцию» от «напрямую».

## Последствия

- `completed` становится достижимым и защищённым: опора для гейта отзывов в OP-037.
- Завершённый проект нельзя вернуть в работу; при ошибочном завершении нужно решение Platform Owner через прямое вмешательство в БД.

## Риски

- Нет сценария спора/возврата после завершения. Принято сознательно; фиксируется как возможное расширение.
- Миграция применяется на `apps-serve` отдельным шагом после проверки; до применения кнопка вернёт ошибку отсутствующей функции.
